# CAD iteration note

Optional prompts for a short project-log entry after a meaningful change. Use only what helps; do not fill every row or delay the preview.

- **Goal / baseline:** named feature, previous review revision, current revision and intended fixed interfaces.
- **Changes since previous review:** requested and incidental changes; lead with consequential differences and their reason/impact. Link the detailed comparison beside the CAD.
- **Decision / drift:** departures from agreed direction or assumptions, when surfaced, and actual user decision before implementation.
- **Preview:** clear whole assembly, source revision and image path; matching before/after if useful.
- **Change coverage:** actual source/model/part-manifest comparison performed; fields mechanically checked, discrepancies reconciled, and unchecked or unavailable coverage. A handwritten note alone does not prove completeness.
- **Quick functional check:** what actually ran and its result; note known limits or failures.
- **Feedback / next decision:** original request, concrete review question and actual user response. Implemented does not mean accepted.
- **Handoff:** editable source and delivered exports from the same revision, when applicable.

Record a targeted risk check only when needed. Add physical-test evidence for requested prototype work or a concrete risk. Add detailed assembly-walkthrough findings only when the user explicitly requested that walkthrough. Unknown or untested is a valid status; this note must not trigger extra tests or reviews.
