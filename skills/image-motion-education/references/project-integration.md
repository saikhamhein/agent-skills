# Integrating into an educational project

Read the consuming repository's current instructions and existing lesson records. This reference explains integration; it is not a new project template or a reason to migrate old lessons.

## Myanmar Science Visuals

Use the installed, pinned Motion Studio skill and native FFrames pipeline. Verify it with `node scripts/install-motion-studio.mjs --check` from that checkout. Read its native, science and review references and the project's official upstream API links before writing Rust. Retain Cargo.lock, generator provenance, current safe areas and existing asset locations.

Illustrated PNG poses can become native media assets with an explicit timeline. Keep the fixed five-zone Myanmar Edu identity, faint grid, established palette roles, baselines and typography. Stage the illustration inside the diagram zone. A paper or painted character does not authorize a paper-textured background or a new title treatment. Preserve the concept-name opening for about one second within the requested runtime.

Precompute compatible facial in-betweens with the bundled helper, then load the transparent PNG sequence as native media. Select one image per output frame during that transition; do not dissolve whole bodies in FFrames. Generated hand/body action states use their own stepped intervals. Keep their common canvas and anchor.

Implement pose selection using integer, end-exclusive frame intervals. Apply transforms to a shared contact anchor. Keep equations, exact geometry, text and the physical state in Rust/SVG. Reuse the existing audio/caption pipeline. Do not install Pillow/OpenCV merely to assemble a lesson already supported by the native renderer.

Use conversational Unicode Burmese and the current repository font tokens. As of the owner's 2026-10-07 selection, `identity::CURRENT_BURMESE` uses 50 px headline, 46 px second title line and 40 px captions at 1080×1920, Noto Sans Myanmar Regular/400. Mixed Latin/digits in those lines share the role's size and require the correct Latin font. Do not shrink captions or body text below the approved 40 px floor; rephrase/split and preserve reading time. Current project rules take precedence if these values change.

Do not estimate Burmese narration from spaces. Use actual measured audio or caption-led timing. Inspect native glyph ink, shaping and stacked marks; retain pending owner/fluent-reader language review truthfully. Never label an unreviewed draft approved.

Use original or licensed audio as requested, preserve its provenance and include required visible music credit. Scientific correctness, curriculum mapping, visual review and language review are distinct evidence. Keep unknown textbook information unknown.

Copy the exact owner-approved MP4 to the existing release folder and follow the simple project README handoff. Do not rerender solely to call it final or add mandatory approval forms. Social posting obeys the current task and repository pause rules; generating this skill or a local video does not resume Facebook activity.

## Other projects

Adopt their native renderer and typography when available. For a new standalone project, choose dimensions, frame rate, language and audio from the user's brief. If unspecified, a vertical 1080×1920/30 fps educational draft is a reasonable assumption, but do not transplant Myanmar Edu branding into unrelated work. Establish original sources, model limits and a check for understanding before polishing the character performance.
